# Plan: Natural understanding + contextual Terminal interaction + living UI + Pill 2.0
_Locked via claudex-loop — by Claude + Todor. Branch: fix/tool-calling-reliability. NO COMMITS, NO PUSHES. Rev 5 (post Codex round 4)._

## Goal
Make Artemis resolve natural speech against real screen/terminal/conversation context instead of transcribing it literally ("type one and press enter" → `1` + Enter when a numbered menu is visible), keep every simple command brain-free and every action inside the existing permission/taint runtime, replace robotic replies with deterministic natural phrasing, and redesign the dashboard and floating pill so the UI visibly reflects what Artemis is actually doing. Interpretation and execution work fully offline with the local Ollama brain (speech transcription/TTS remain the existing Deepgram paths — offline claims are scoped to everything after transcription, including the typed-input path end to end).

## Approach

### Phase 1 — Interpreter contracts + working context (new modules, pure, unit-tested)
1. **`workingContext.js`** (new): ephemeral interaction context, injectable clock, single in-process store guarded by an **active-interaction lease** — contextual turns are serialized (queue depth 1) so overlapping surfaces (dashboard, pill, phone) can never interleave recall state (Codex r2 #6). Records only **successful validated calls, exactly as validated**: `lastCommand` {tool, args, risk, targetId, contextHash, at}, `lastToolRun` {name, family, ok, at}, `lastOptionSet` {options[{n,label}], promptKind, evidence, at}, `lastPrompt`, `currentTask` {turnId, label, state}. TTLs: option set / visible prompt **90s**, last command 15 min, tool run 30 min. `currentTask` is turn-scoped with explicit lifecycle — cleared on done/error/cancel/disconnect. Nothing persists to disk.
2. **`naturalCommand.js`** (new): the Natural Command Interpreter. Layered, deterministic-first, pure:
   - `stripAnsi(text)` + `parseTerminalTail(text)` — operate on the **trailing region only** (last ~40 lines after ANSI/control stripping): extract a numbered menu (`1. Qwen` / `1)` / `[1]`) and/or pending prompt (`[y/N]`, `[Y/n]`, trailing question, Claude Code approval phrasing) **only when it is the final interactive block** — if any shell-prompt line (`$`/`%`/`❯` shapes) or completion output follows the block, the menu is dead and is not returned (Codex r2 #5). Result carries a `tailHash` binding the parse to the exact buffer state. Stale scrollback is never a resolution source.
   - `deicticCommandForText(utterance)` — classify contextual phrasings: ordinal/number/label selection ("pick the first one", "choose number two", "go with the third option", "select Qwen"), submit-only ("press enter"), repeat ("run that/it again", "do the same thing again"), relay ("tell Claude yes/no/…"), deictic typing ("type one and press enter" with a bare ordinal/number payload). Pure regex, no model.
   - `resolveDeictic(deictic, {terminalTail, working, utterance})` — deterministic resolution with evidence: ordinal → visible option number; label → unique case-insensitive label match; repeat → `working.lastCommand`; relay → **visible prompt required** (Q1), answer form derived from the prompt (`[y/N]` → `y`, natural question → `yes`); deictic typing → number only when that option is visible; **press_enter** → a candidate only when the foreground is supported Terminal.app AND fresh evidence shows a prompt/input awaiting submission — otherwise clarify (Codex r2 #8). Output: `{outcome: "action"|"clarify", action?, params?, evidence: {windowId, tabId, tailHash, optionLabel?, promptKind?}, question?}` — evidence carries stable Terminal **window/tab identity** from perception, compared before every keystroke (Codex r2 #4). **Natural-vs-literal:** explicit literal markers ("type the words …", "literally", quoted payload) always win as literal; bare ordinal + visible menu resolves; bare ordinal + no menu clarifies — never a blind literal, never a blind action.
   - **Semantic tier — candidate-constrained, never generative.** `candidateActions(utterance, context)` deterministically derives a **closed set** of permitted outcomes (select_option(n) per visible option, answer_prompt(yes|no) when a prompt is visible AND the utterance addresses it, press_enter per the rule above, repeat_last when one exists, type_literal(text) where text must be a normalization of the *utterance* only, clarify). `interpretWithBrain({utterance, candidates, context, callBrain})` asks the model to **choose among the candidates** and return strict JSON `{choice, confidence, explanation}`; unknown fields, out-of-set choices, or any parameter not in the candidate are rejected. **Acceptance requires confidence ≥ 0.8 AND deterministic corroboration; anything lower or ambiguous becomes clarification** (Codex r2 #9). Screen/terminal text can therefore never originate a command, URL, path, or capability — it only ever *narrows* what the user's own words proposed. `callBrain` injected for tests.
3. **`toolRegistry.js` surgery**:
   - `terminalTypeForText` gains `deictic: true` for bare ordinal/number/submit-only payloads without a literal marker; **`computerControlIntent`-style direct dispatch must decline deictic parses** (routing fix, Codex #2).
   - Add `FAMILY_PATTERNS.contextual` AND add `"contextual"` to the `forceFamilies` of `computer_control` and `run_command` so the family is actually routable (Codex #1); `contextual` joins ACTIONABLE_FAMILIES.
   - Relay-shaped `computer`-family utterances ("tell Claude yes") route to the contextual tier explicitly (Codex #3).
   - `needsConfirmation` gains a `contextDerived` input: an effectful payload that did not come verbatim from the user's own words forces the confirm gate unless it passes the interactive-input policy below (Codex #6).
4. **`commandPolicy.js` addition — interactive-input policy, allowlist-shaped** (Codex #7, hardened per r2 #2 and r3 #2/#3/#4): `classifyInteractiveInput({payload, optionLabel, promptHeader, promptKind, userNamed})` auto-executes **only** when the bound option/prompt is visible (fresh evidence) AND one of:
   - (a) the user themselves named the effect (spoke the label — "select Qwen" — or dictated the answer — "tell Claude yes", "type y") **and** the visible prompt/option text carries no destructive/consequential vocabulary (delete, erase, overwrite, uninstall, reset, force, push, deploy, pay, send, grant, all files, sudo, …) — a destructive prompt confirms once even when explicitly addressed;
   - (b) an ordinal/unnamed selection targets a **recognized benign selector class** — the menu header/prompt matches a small allowlist (choose/select a model, language, theme, voice, option list of plain product names) — generic "plain noun" labels are NOT exempt (a noun like "Production" or "Administrator" is opaque).
   Everything else — opaque positive labels ("Continue", "Proceed", "Yes"), action-shaped labels, unrecognized menu classes, unknown interactive effects — **confirms first**. **press_enter routes through this same policy**: it auto-executes only when the pending input line is content Artemis itself typed this turn or the prompt class is recognized benign; an unknown highlighted control confirms. **Single-key input is context-sensitive** (Codex r4 #1): a dictated `type y` / `type d` (any ≤2-char payload) with Terminal foreground is not "inert type_text" — a raw-mode TUI executes it immediately — so it routes through contextual revalidation + this interactive policy + the destructive-prompt screen before any keystroke. Shell `classifyCommand` continues to govern actual shell command text (repeat, type_and_run of commands).

### Phase 2 — Contextual Terminal understanding (server integration)
5. **`contextualDispatch.js`** (new, dependency-injected): one dispatcher owning the whole tier — trigger detection, context collection, resolution, policy, execution handoff — with injected `{perception, working, callLocalBrain, callCloudBrain, runSkill, pend, policy, log}` (cloud chooser injected explicitly — Codex r3 #1). `server.js` wires the real deps; **both `/api/chat/stream` and `/api/chat` call it** (Codex #16, #21). Flow:
   - Trigger: intent family `contextual`, `computer`+`terminalType.deictic`, or `computer`+relay shape.
   - Context: `foregroundApp()` always; terminal tail only when terminal-relevant; **no OCR in this tier**. Contextual terminal control requires foreground **Terminal.app** — iTerm or anything else gets an honest clarification, never cross-app typing (Codex #11). Perception failure → clarify.
   - Deterministic resolution → semantic candidate-choice via the **local** brain → in hybrid mode, one more candidate-choice pass with the **cloud** brain (same closed candidate set, same strict JSON, same threshold — the generative forced-tool loop is NEVER the fall-through for contextual turns; `contextual` family turns that stay unresolved end in clarification, and the family never force-feeds tools to the ordinary loop) (Codex r2 #1); offline/local-only → deterministic clarification, zero cloud (Q2).
   - **Execution seam:** a shared `dispatchOrPend(name, params, {contextDerived, evidence, revalidate})` helper — validate via `validateToolCall`, precheck, then either run through `dispatchDirectSkill` or raise the standard confirm gate. The pending record gains an **immutable authorization envelope** ({evidence, contextDerived, revalidate marker}) carried through `createPending`, and `/api/confirm` re-runs validation + precheck + contextual revalidation immediately before confirmed execution (Codex #8, r2 #3).
   - **Revalidation against TOCTOU** (Codex #9, r2 #4): resolutions carry `evidence` {windowId, tabId, tailHash} (perception extended to return stable window/tab identity); immediately before any keystroke — and again when a confirm gate is answered — the terminal tail and target identity are re-read and the action aborts with an honest line if the menu/prompt changed or the target tab differs.
   - Bare "yes/no" stays owned by the confirm gate (Q1); the relay resolver only fires on explicit addressing.
   - Emits SSE lifecycle (`intent_pending` → `interpreting` → `tool` …) and **structured decision logs**: {turnId, tier, resolver, contextAgeMs, tailHash, candidateCount, verdict, policyReason, brainMs} — redacted, never raw terminal content (Codex #22).
6. **`press_enter`** becomes a real validated `computer_control` action backed by a new `macPerception.pressEnterInTerminal()` keystroke primitive (System Events "key code 36" scoped to Terminal.app, same permission/error vocabulary as typeInTerminal) — "press enter" and submit-after-type_text stop being unimplementable (Codex #4).
7. **`localBrainFetch()`** in server.js (Codex #14): single-candidate fetch for `ollama:*` brains — asserted loopback endpoint, ~3s budget, no chain failover, no cooldown mutation. Its cloud sibling **`cloudCandidateFetch()`** (Codex r4 #3): selects exactly one non-local brain, makes one bounded no-tools request returning candidate-choice JSON only, no chain fallback, no retry. The interpreter uses only these two, so chain state can never reroute interpretation.
8. **One abort-safe Terminal-UI mutex** (Codex r3 #5, narrowed per r4 #2) wraps **perception reads + visible keystroke actions only** — contextual revalidate-and-type sequences, direct `computer_control` typing, and `/api/confirm` execution of keystroke tools — acquired before revalidation, released in `finally`, with an abort signal threaded through acquisition and execution. `run_command` (headless shell, up to 120s) does NOT hold it; workingContext updates are separately atomic.
9. **Screen-derived text is persistently untrusted** (Codex r3 #6): replies that embed terminal labels/prompts (selection echoes, clarifications quoting a menu) carry the same provenance marking the mail path uses — the turn is flagged untrusted (`mailUntrusted`-style screen taint over the existing SSE channel + history redaction in `sanitizeMessages`), so a malicious label can't become trusted conversation history for a later model turn. Labels are also sanitized (safe charset, length-capped) before echoing.
10. `workingContext` recording at the three dispatch seams + option-set/prompt recording from every successful terminal read (including model-initiated `read_screen`).

### Phase 3 — Natural response layer
9. **`naturalReply.js`** (new): deterministic phrasing with small variation pools and injectable picker (tests pin variant 0). Covers: terminal open, type-only, type+run, option selection ("Got it — picked option 1, Qwen."), press-enter, repeat, revalidation aborts ("The menu changed, so I didn't touch it."), offline ("I'm offline, but local commands still work."), no-brain, failure lines (absorbing `terminalFailureLine` codes), clarifications. Wired into computerSkills summaries, contextual/direct dispatch replies, and the offline/error strings in server.js. Models phrase only genuinely open-ended answers.

## Key decisions & tradeoffs
- **Q1 (locked):** bare confirmations only answer Artemis's own confirm gate; Terminal relay needs explicit addressing AND visible-prompt evidence; no yes→y shortcut.
- **Q2 (locked, transport sharpened in Rev 3/4):** local-first; in hybrid mode an unresolved interpretation gets exactly one more candidate-choice pass on a cloud brain (same closed set, same threshold) — the ordinary generative forced-tool loop is prohibited for contextual turns; offline/local-only has zero cloud fallback.
- **Q3 (locked, sharpened by review):** auto-execute needs unambiguous target + fresh corroborating evidence (tailHash) + benign interactive-input classification; everything else confirms. Interpreter never bypasses validateToolCall/taint/commandPolicy/needsConfirmation/prechecks — and `contextDerived` payloads get their own confirmation pressure.
- **Semantic tier is a chooser, not an author** (Codex #5/#15): the local model selects among deterministically derived candidates; screen text can narrow but never originate an action.
- Deterministic resolvers before any model call; one DI'd dispatcher shared by both chat endpoints.
- One presence bus extended with ownership + turn/seq rules; view-models stay pure.
- Dashboard v2 evolved in place; v1 rollback; no framework. PillController extended only for sizing/messaging.
